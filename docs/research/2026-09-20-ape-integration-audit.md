# APE integration audit — TypeSafe AI Jev

**Snapshot:** branch `RileyHinsperger/axiom-revenue-engine-rebuild`, HEAD `02e0c5a` (`feat: trust assessments after durable reload`); two preexisting untracked `private-kw-assessment-progress` files preserved. No tests/builds run. `rg` found no JEV/TypeSafe references; `ScrapeJobEvent` is legacy job telemetry, not JEV.

The repository has two generations. Legacy intake/scrape/outreach remains in `src/lib/scrape-engine.ts`, `scrape-jobs.ts`, `auto-pipeline.ts`, `lead-qualification.ts`, `axiom-scoring.ts`, `outreach-automation.ts`, `gmail.ts`, and `src/app/api/**`; CSV export is `src/lib/export/{csv.ts,export-presets.ts}` with `/api/leads/export`. New evidence-first Revenue Engine code is under `src/lib/revenue-engine/` and the owner read models/UI (`owner-lead-{projection,read-model,detail-read-model}.ts`, `src/app/leads`, `src/components/leads`).

Key seams: `src/engine/adapters.ts` defines typed `SourceAdapter`, `AuditAdapter`, `ContactAdapter`, `VerificationAdapter`, `MailboxAdapter`, cost receipts, and remaining budget; `src/lib/revenue-engine/ai/types.ts` defines `AIProvider`; `ai/openai-responses.ts` is the only concrete new provider. Qualification is deterministic in `qualification.ts` (five visible scores; shadow-only), assessment in `lead-assessment.ts`, and evidence contracts in `evidence.ts`, `website-audit.ts`, browser/capture/artifact modules. The engine Worker (`src/engine/worker.ts`) only validates then halts: no queue, schedule, binding, credential, or execution path.

Budget is enforced structurally in the new path: workflow `maxCostUsd: 0`, fixtures/adapters use zero provider operations/cost, and safety scans assert this. Environment autonomy switches default off/zero in `src/lib/env.ts`; the master plan reserves C$50/month and describes future provider budgets, but no live Jev budget/ledger integration exists. Legacy Gmail/automation has real send code and broader limits, though global switches remain off by default.

Best Jev seam: add a separate `DecisionProvider.evaluate` adapter beside `AIProvider.generateStructured`, translating Jev Choice/Score/Noul responses into schema-validated, evidence-bound advisory results; keep it disconnected until provider, model/version, cost, retry, and golden-evaluation gates exist. Do not wire Jev into `worker.ts` in the same milestone.

Highest-ROI opportunities: (1) a fixture-only Jev adapter behind a separate `DecisionProvider`; (2) pilot cost reservations shared by Jev and its nano fallback; (3) completing the existing assessment path so comparisons can use valid evidence; (4) measuring business-fit and research-triage accuracy before any scoring migration; (5) owner-visible decision and evidence provenance. Legacy scoring migration is a later independent project, not a prerequisite for Jev.

Constraints: evidence must retain URL/time/method/confidence/audit version; AI output must be schema/evidence validated and model/prompt versioned; only verified email may eventually automate; all production/provider/deployment actions remain separately gated. Relevant decisions: ADR 0001, 0002, 0027, 0038; `docs/RUNBOOK.md`.
